# Как работает GSocket - Архитектура подключения

## Важно понять!

**GSocket НЕ использует hostname или IP адрес для подключения.**

## Архитектура GSocket

### Традиционное подключение (SSH, RDP):
```
Client ──> Подключение к IP:Port ──> Server
         (нужен IP/hostname и порт)
```

### GSocket подключение:
```
Host ──> GSRN Relay Network <── Panel
     (оба используют ОДИН И ТОТ ЖЕ секрет)
```

## Как это работает

### 1. На удаленном хосте (целевая машина):

```bash
# Генерируем уникальный секрет
gs-netcat -g
# Вывод: 6fzXHFQ7gNwNEpmKvGKZvZYxZw4Q4KLrgvnF2k2pCGk=

# Запускаем агент с этим секретом
gs-netcat -l -s "6fzXHFQ7gNwNEpmKvGKZvZYxZw4Q4KLrgvnF2k2pCGk=" -e /bin/bash -D
```

Хост теперь:
- ✅ Ожидает подключения в глобальной GSRN сети
- ✅ Идентифицируется по секрету
- ❌ НЕ открывает никаких портов локально
- ❌ НЕ требует публичного IP
- ❌ НЕ требует проброса портов/NAT

### 2. В панели управления:

Добавляем хост:
- **Hostname**: `web-server-01` ← Это просто название для вашего удобства!
- **IP Address**: `192.168.1.100` ← Опционально, для справки
- **GSocket Secret**: `6fzXHFQ7gNwNEpmKvGKZvZYxZw4Q4KLrgvnF2k2pCGk=` ← **ЭТО используется для подключения!**

### 3. Когда панель отправляет команду:

```
1. Панель говорит GSRN: "Найди соединение с секретом 6fzXHFQ..."
2. GSRN находит хост с таким же секретом
3. Устанавливается зашифрованное соединение
4. Команда выполняется на хосте
5. Результат возвращается через GSRN
```

## Ключевые моменты

### ✅ Что ВАЖНО:

1. **Секрет (Secret)** - это единственный идентификатор подключения
2. **Оба конца** (хост и панель) должны использовать **ОДИНАКОВЫЙ секрет**
3. **Каждый хост** должен иметь **уникальный секрет**

### ❌ Что НЕ важно для подключения:

1. Hostname - используется только для отображения в интерфейсе
2. IP Address - сохраняется только для справки
3. DNS имена - не используются
4. Открытые порты - не требуются
5. Публичный IP - не требуется

## Преимущества такой архитектуры

### 🔒 Безопасность:
- Нет открытых портов на хостах
- End-to-end шифрование (AES-256)
- Секрет никогда не передается по сети в открытом виде

### 🌐 Работа через NAT/Firewall:
- Не нужен публичный IP
- Не нужен проброс портов
- Работает из-за любого firewall (если разрешен исходящий HTTPS)

### 🚀 Простота:
- Один секрет = одно подключение
- Автоматическое переподключение
- Работает везде где есть интернет

## Практический пример

### Сценарий: Управление домашним компьютером

#### Традиционный способ:
```
❌ Нужен статический IP или DynDNS
❌ Настройка проброса портов в роутере
❌ Открытие SSH порта (22) в интернет
❌ Риск атак на SSH
```

#### С GSocket:
```
✅ Запустил gs-netcat -l на домашнем ПК
✅ Скопировал секрет в панель
✅ Работает! Подключаюсь откуда угодно
✅ Никаких настроек роутера
✅ Никаких открытых портов
```

## Как добавить хост в панель

### Шаг 1: На целевом хосте

```bash
# 1. Сгенерировать секрет
SECRET=$(gs-netcat -g)
echo "Ваш секрет: $SECRET"

# 2. Сохранить секрет в безопасном месте

# 3. Запустить агент
gs-netcat -l -s "$SECRET" -e /bin/bash -D
```

### Шаг 2: В веб-панели

1. Нажать "Add Host"
2. Заполнить поля:
   - **Hostname**: `my-laptop` (любое удобное имя)
   - **IP Address**: (можно оставить пустым)
   - **GSocket Secret**: вставить секрет из шага 1
3. Нажать "Add Host"

### Шаг 3: Проверка

Панель автоматически:
- Попытается подключиться используя секрет
- Проверит доступность хоста
- Покажет статус (online/offline)

## Множественные хосты

Каждый хост = уникальный секрет:

```
Хост 1: gs-netcat -l -s "SECRET_AAA..." -e /bin/bash -D
Хост 2: gs-netcat -l -s "SECRET_BBB..." -e /bin/bash -D
Хост 3: gs-netcat -l -s "SECRET_CCC..." -e /bin/bash -D
```

В панели:
```
- web-server-01    → SECRET_AAA...
- db-server        → SECRET_BBB...
- backup-server    → SECRET_CCC...
```

## GSRN (Global Socket Relay Network)

### Что это?

Глобальная сеть relay серверов, которая:
- Маршрутизирует зашифрованные соединения
- Работает как "телефонная станция" для gsocket
- Бесплатна и открыта для использования

### Как работает GSRN?

```
Host (secret: AAA)
    ↓
    ↓ Подключение к GSRN
    ↓
GSRN Relay (помнит: secret AAA = этот хост)
    ↑
    ↑ Запрос подключения к secret AAA
    ↑
Panel (ищет secret: AAA)
```

### Можно использовать свой GSRN?

Да! См. `CUSTOM_GSRN_GUIDE.md`

## Безопасность секретов

### ✅ Хорошие практики:

```bash
# Генерация через gs-netcat (криптографически стойкая)
gs-netcat -g

# Хранение в переменных окружения
echo "GSOCKET_SECRET=xxx" > /etc/gsocket.env
chmod 600 /etc/gsocket.env

# Использование через env
GSOCKET_ARGS="-s $(cat /etc/gsocket.env | cut -d= -f2)" gs-netcat -l -e /bin/bash -D
```

### ❌ Плохие практики:

```bash
# НЕ ДЕЛАЙТЕ ТАК!
gs-netcat -l -s "password123" ...  # Слабый секрет
gs-netcat -l -s "secret" ...       # Предсказуемый секрет
history | grep gsocket             # Секрет в истории команд
```

## Troubleshooting

### Хост показывает offline

**Проверьте:**
1. Агент запущен на хосте? `ps aux | grep gs-netcat`
2. Секреты совпадают? (опечатки, пробелы)
3. Интернет есть на хосте? `ping 8.8.8.8`

### Команды не выполняются

**Проверьте:**
1. Агент запущен с флагом `-e /bin/bash`?
2. Права доступа у агента?
3. Логи панели: `docker-compose logs web`

### "Connection refused"

**Причины:**
1. Агент не запущен на хосте
2. Разные секреты у хоста и панели
3. GSRN недоступен (проверьте интернет)
